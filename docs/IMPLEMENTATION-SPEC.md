# Unsleep 首版实施规格

日期：2026-10-24。状态：首版已按当前 Windows 11 x64 无电池设备范围完成交付验收；未运行的设备与平台项目保留限制，详见 GitHub Issue #13。授权以 AGENTS.md 及人类明确决定为准。

## Problem Statement

用户需要一个独立、极简的 Windows 托盘工具，在下载、编译、计算、备份期间请求阻止自动休眠，必要时保持屏幕常亮，同时避免耗尽移动电脑电池。原有 Caffeine 兼容重建中的旧参数、模拟输入和复杂条件不再符合已确认产品范围。实施授权遵循 AGENTS.md 及人类在任务中的明确决定。

## Solution

提供常驻托盘的手动启停工具，具备四档持续时间、仅本次生效的屏幕常亮与三档电池保护。停止后留在托盘，恢复 Windows 正常电源管理；不主动触发休眠。

协作流程、项目角色与授权边界见 [AGENTS.md](../AGENTS.md)，环境准备与构建见 [README](../README.md#开发环境与构建)，依赖约束见 AGENTS.md。

## User Stories

1. 作为后台任务用户，我希望启动程序即开启防休眠，以便立即保护正在执行的任务。
2. 作为用户，我希望默认允许息屏、持续时间不限，以便减少不必要的设置。
3. 作为用户，我希望在托盘手动启停，以便按需使用并保留快速入口。
4. 作为阅读或演示用户，我希望选择本次保持屏幕常亮，以便不中断观看。
5. 作为用户，我希望停止后重置屏幕常亮，以免下一次意外保持显示器开启。
6. 作为用户，我希望选择不限时、30 分钟、1 小时或2 小时，以便匹配任务长度。
7. 作为用户，我希望切换时长从当下重新计时，以便清楚知道何时停止。
8. 作为用户，我希望到期只停止防休眠并留在托盘，以便稍后继续使用。
9. 作为移动电脑用户，我希望默认在未插电且电量不高于20%时停止，以便保留电池余量。
10. 作为移动电脑用户，我希望选择10%、20%或30%并记忆选择，以便适合我的电池习惯。
11. 作为用户，我希望低电量停止时同时释放屏幕请求，以便保护设置确实生效。
12. 作为用户，我希望插电后仍保持停止并由我手动重开，以便避免意外恢复。
13. 作为用户，我希望锁屏后继续请求后台唤醒且允许息屏，以便兼顾任务和锁屏。
14. 作为用户，我希望合盖遵循 Windows 设置，以便保留系统行为。
15. 作为用户，我希望手动睡眠或休眠后保持停止，以便工具尊重我的操作。
16. 作为用户，我希望左右键打开同一个原生菜单，以便操作一致。
17. 作为用户，我希望从图标和普通悬浮提示获知实际状态、剩余时间或停止原因，以便判断工具是否有效。
18. 作为用户，我希望低电量停止或请求失败仅通知一次，以便看到必要反馈而不被反复打扰。
19. 作为用户，我希望普通启停和到期不弹通知，以便保持安静。
20. 作为用户，我希望退出释放所有本工具请求，以便恢复正常电源管理。
21. 作为用户，我希望重复启动不产生多个实例或改变当前使用，以便状态保持一致。
22. 作为用户，我希望 Explorer 重启后恢复托盘图标，以便仍能操作工具。
23. 作为用户，我希望产品如实说明设备电源限制，以便不把请求成功误认为后台任务一定持续运行。
24. 作为维护者，我希望交付保留许可证、资源来源和验证记录，以便可靠接手。

## Implementation Decisions

### 决策来源与权责

- 产品范围保留人类最终确认的全部决策；下列异常、时钟与状态细节是本次补充的技术规则，后续不能以实现方便为由改变产品目标。
- 复用现有 C++23/Win32 核心模型与系统适配的分离方式，简化旧兼容逻辑；本规格不要求保留旧接口。术语表或 ADR 按实际需要建立。

### 实施前置条件

执行环境须有项目本地化、配置加载、无工具报告及有工具 CLI 任务—报告闭环证据，包含子进程数据位置核对。具体任务与完成状态见 GitHub Issues #2—#6；业务准入还需人类明确恢复授权、目标平台和可用实机。目录约定不等于系统沙箱，不要求越界拒绝或网络封锁探针。

### 工程约束

- 核心模型保持不调用 Windows API，以明确输入产生可观察状态和动作；Windows 适配负责系统采样、托盘、会话/电源事件及请求结果回传。现有 include/unsleep/core.hpp、src/core.cpp、src/win32.cpp 是迁移起点，不冻结旧接口。
- 菜单、图标、字体、窗口、设置及电源请求等资源明确所有权并可靠释放，优先沿用 RAII；窗口关联指针不拥有业务对象。任何外部或回调数据在使用前校验有效性。
- Windows 回调捕获异常，避免异常跨越系统回调边界；错误反馈遵循本规格的一次通知、状态如实显示规则，不恢复旧错误窗口或面板。
- 继续使用高等级编译告警与既有安全编译选项；核查资源来源及许可证。静态措施不构成所有路径安全或行为正确的证明。
- 单项 Issue 纳入其涉及的上述约束及行为验收；OpenPi 报告实际差异、验证与未运行项，由 ChatGPT 验收。旧解析、按键及 tick 计时不迁入新规格；行为测试入口见 Testing Decisions。

### 状态、菜单与持久化

- 核心区分运行/停止、系统/屏幕请求、截止时间、电池阈值、锁定状态与停止原因；系统适配负责采样、施加请求及回报成功/失败。界面展示已确认施加的状态，不把期望状态当成成功。
- 原生菜单仅有防休眠开关、保持屏幕常亮、持续时间、电池保护、退出；左右键一致，无双击动作、独立状态窗口或自绘面板。
- 图标采用人类选定的 GPT 咖啡杯稿；运行有蒸汽，停止为冷杯，形状和颜色均可区分。屏幕与时钟角标体现常亮与有限计时；常亮已勾选但因锁定/未知会话状态暂缓时使用虚线屏幕，区别于请求实际生效。应用图标使用无配置角标的基础咖啡杯。完整勾选配置及电池阈值同步到悬浮提示，保持原生提示长度限制；明暗任务栏均保持对比度。OpenPi 负责原稿的技术转换与接入，不重新设计造型。
- 启动默认运行、允许息屏、不限时；每次从停止重新开启也使用这组默认值。停止时清除截止时间和屏幕常亮，保留本次选定时长不再自动重启。停止时屏幕及持续时间控件禁用，电池阈值仍可修改。
- 只持久化电池阈值；缺失或非法配置回退20%。写入失败仍使用本次内存选择，并在普通悬浮提示中说明未保存，不增加弹窗。配置存储使用最小的应用专属用户设置；具体平台存储方式在实施任务中确定，不新增同步或通用配置框架。
- 运行时切换有限时长从当前单调时刻重新计算截止时间；不限时清除截止时间。墙上时钟、时区变更不影响计时；回调延迟按实际经过时间计算，不能按 tick 次数累计。达到截止时间后的首个处理周期即停止，正常事件循环下目标延迟不超过1秒。
- 所有停止路径释放系统与屏幕请求；停止幂等，不主动触发睡眠。并发事件顺序为退出、睡眠/恢复、低电量或电池未知、请求失败、到期、普通操作；停止后到达的旧回调不能重新开启。

### 电池、睡眠与错误边界

- 在启动、手动开启、阈值变更、电源事件及运行中的周期采样时检查电池。事件缺失时以不超过5秒的周期补查。未插电且电量等于或低于阈值时拒绝开启或立即停止；没有绕过选项。
- 明确无电池的设备不触发阈值；明确插电可运行。电源来源未知，或有电池且未确认插电而电量未知时，采用保守规则：停止/拒绝开启，提示“电池状态未知，防休眠已停止”，按一次系统状态读取失败反馈，不假造电量。数据恢复、充电或插电均不自动重开。
- 锁定时释放屏幕请求，继续系统请求；解锁后仅在本次仍运行且选择过屏幕常亮时恢复屏幕请求。锁屏不重置倒计时、不阻止锁定。
- 不改变合盖策略，不注册阻止用户睡眠的机制。收到系统睡眠通知即停止；恢复事件也保守保持停止，避免漏掉睡眠前事件而重新施加请求。不依赖可靠区分睡眠来源，系统自动睡眠后的恢复也不自动重启。休眠、睡眠及 Modern Standby 的事件能力须实机确认。
- 请求施加失败时撤销本次请求、进入停止并清除本次选项，提示失败原因，一次失败只通知一次；不循环重试开启。释放失败如实显示释放未确认，并记录诊断，不能报告已成功释放。退出仍尝试清理所有自有句柄/线程请求。
- 低电量停止每次使用最多通知一次；请求或系统读取失败按故障事件去重，重复回调不重复通知。普通启停与到期无通知。系统屏蔽通知时仍通过托盘提示呈现结果。
- Windows 请求成功只表示系统接受调用；不承诺阻止强制睡眠、用户操作或所有 Modern Standby 电池场景。
- 可靠性保留资源管理、单实例、Explorer 重建后的托盘恢复、必要错误反馈与许可证/资源出处。第二实例退出且不重置第一实例；托盘恢复不改变当前状态或截止时间。

## Testing Decisions

测试边界已由人类确认：主要自动化入口是核心状态模型的行为边界，Windows 行为采用实机验收，执行环境独立验收。优先复用现有“输入→模型→可观察动作/状态”边界；允许在此输入单调时间、系统事件和请求结果，不新增散落的私有函数测试入口。只验证外部行为，不绑定内部字段、调用次数或具体 API 选型。

现有核心测试具备状态与边界输入先例，可复用其组织方式；旧解析、模拟按键、计划与兼容性断言应随移除功能淘汰。历史2139项检查、5000组畸形输入及旧比较结果都不是本规格通过证据。

### 验收矩阵（未来由 OpenPi 执行并报告）

| 编号 | 边界 | 通过条件 |
| --- | --- | --- |
| E1 | 执行环境 | 接入、项目本地化及有工具 CLI 任务—报告闭环有可复核证据，含子进程数据位置；未验证项不计通过，不要求系统沙箱验收 |
| C1 | 启停 | 启动及重新开启默认系统请求、不限时、允许息屏；手动停止、到期、低电量、失败均停止且不退出，清除本次屏幕选项 |
| C2 | 计时 | 四档完整覆盖；切换重新计时；截止前、恰好截止、超过截止、重复回调、延迟回调、墙上时钟跳变均符合规则 |
| C3 | 电池 | 三阈值各覆盖阈值前/等于/低于；插电、拔电、无电池、未知来源/电量、运行中改阈值及恢复数据；禁止自动恢复 |
| C4 | 锁定和睡眠 | 锁定保留系统请求且释放屏幕；解锁按本次选择恢复；睡眠/恢复停止；重复及交错事件不能重开 |
| C5 | 故障和通知 | 系统/屏幕施加失败、释放失败、设置读写失败均如实显示；通知去重；普通操作与到期不通知 |
| W1 | 托盘 | Windows 实机验证菜单仅五项、左右键一致、无双击行为、勾选/禁用正确、运行/停止图标及提示正确，第二实例不改变当前状态，Explorer 重启可恢复 |
| W2 | 电源 | 实机验证系统/屏幕请求施加与释放、锁定解锁、手动睡眠及休眠恢复、合盖遵循系统；记录系统电源请求证据，不只看图标 |
| W3 | 设备限制 | 有电池设备验证阈值和插拔电；Modern Standby 记录型号、电源状态、设置和实际限制，无法保证的场景如实标记；未具备设备时标记未运行 |
| W4 | 交付可靠性 | 重新启动仅恢复阈值；正常退出释放请求；审查句柄/资源清理与异常路径；核对资源许可证和来源；支持的架构实际构建并运行冒烟验收 |

Windows 支持版本及发布架构在首个业务任务前由现有构建基线与可用实机确定并记录，不能从历史 x86/x64 记录推定当前支持。每次报告记录代码版本、工具链、环境、命令、退出码、产物和证据；静态检查、历史结果、本轮实际运行、未运行分别列出。ChatGPT 按矩阵接受或返工；人类决定发布。

人类已确认当前没有可用于验收的电池电脑，先完成当前设备验收并明确电池限制。因此交付验收须单独列出当前 Windows 11 x64 无电池设备结果；真实低电量、插拔电及合盖等缺设备项目保留“未运行”，不能用核心模型或合成消息代替实机通过，也不阻止完成其余当前设备验收。

## Out of Scope

模拟输入、Caffeine 行为及参数兼容、开机自启、快捷键、命令行控制、每日计划、延迟开启、应用/CPU监测、合盖防休眠、阻止锁屏、自绘窗口、外观选择、自定义时长/日期、自动恢复，以及未经授权的主机修复或全局配置。不要求重新开展旧样本比较；是否执行实现、构建、测试或发布仍由项目授权边界决定。
